手机服务器桌面（com.dsh.desk） 开发历程 · 功能说明 · 接口速查 —— 整理于 2026-11-08，当前版本 v0.18.2

一句话：把一台没有 root 的荣耀 X40i（Android 12）做成一台「能自己跑的服务器」—— 开机就是自定义桌面，常驻 HTTP 控制接口，能启停容器里的服务、能远程操作界面、 能和电脑上的 AI 助手双向收发消息，还能把消息显示到 ESP32 小屏、用扬声器朗读。

仓库：github.com/lumingju718-afk/phone-desk（公开，GitHub Actions 自动构建 APK）
设备：荣耀 X40i（DIO-AN00）/ Android 12 / MagicUI 6.1 / aarch64 / 8GB RAM / 无 root
构建：不依赖 Gradle，aapt2 → javac → d8 → 打包 → zipalign → apksigner 纯命令行

一、开发历程（按版本）

起点：把手机变成服务器 v0.5.0

主屏状态面板（时间/电量/温度/内存/存储/IP）、AstrBot & NapCat & SSH 端口探活、 应用内终端、前台服务 + HTTP 控制端（/ping、/exec）、 Termux 桥接（RUN_COMMAND + /callback 回传）、开机自启。

自动化构建 v0.5.1

接入 GitHub Actions：push / PR / 打 v* 标签自动出 APK，打标签自动挂 Release。

远程控制手机界面 v0.6.0

新增无障碍服务 DeskAccessibilityService：点击/长按/滑动、返回/主页/多任务/ 通知栏、节点树读取、按文字点击、填文本、截图。配套 /ui/* 一组接口。 这是后来「我在电脑上操作手机」的地基。

修掉明文 HTTP 的坑 v0.6.1

targetSdk 31 默认禁明文 HTTP，导致主屏 ESP32 状态一直「离线」——加 usesCleartextTraffic="true"。

日志页 + 消息页 v0.7.0 – 0.7.2

服务日志页（AstrBot/NapCat 尾部 3 秒刷新、一键启停）、消息页（助手远程发消息 → 系统通知 + 未读，用户可回复）；新增 /logs /chat /chat/send /svc。 顺带修了 Termux 桥接并发临时文件冲突、日志页退出仍轮询、ANSI 颜色码等问题。

NapCat Token 上主屏 v0.8.0

从容器 config/webui.json 读 token，点按复制、长按打开 WebUI。

给「托管界面」用 v0.9.0

/status 聚合状态、/token 读 NapCat token；所有响应加 CORS， 于是 ESP32 托管的网页能直接跨端口读手机数据。

消息页升级为人机对话程序 v0.10.0 – 0.11.0

消息模型 v2（role/status/conv/reply_to）、投递状态机 （等待应答 → 已回复 / 失败可重试）、三种应答引擎（中继 / OpenAI 兼容 / 本机 AstrBot）、 通知栏直接回复、消息分组、日期分隔、Markdown 渲染。 新增 /chat/retry /chat/config /chat/brain。

公网访问 v0.12.0 – 0.12.1

手机自带受口令保护的网页桌面（8090），配合 Cloudflare 命名隧道 （desk.hjzj114514.cc.cd）。安全边界：8090 只暴露只读/消息/启停， /exec /termux /ui/* 一律 404 —— 执行能力只留局域网 8089。

后记：当前宽带把该域名按名字阻断（同 IP 上别的域名正常），公网访问暂时搁置。

桌面重做：两页 → 三页 v0.13.0 – 0.14.0

删掉终端页/日志页/快捷按钮/应用抽屉，只留可左右滑的桌面： 状态页（neofetch 式）、消息页（终端日志风）、最左新增 Linux 程序页。 切页只刷新当前页以省电。

Linux 页从「能看」到「能操作」 v0.14.2 – 0.15.3

点一下启动/重启（AstrBot / NapCat / dsh）、长按停止（带确认）、 $ run command… 执行任意 Termux 命令。随后尝试把消息页换成内嵌 DSH， 因系统 WebView 太旧（缺 Promise.withResolvers、新语法解析失败）而回退。

GeckoView 内嵌尝试 v0.18.0 – 0.18.2

手工集成 Mozilla GeckoView（91MB AAR + 15 个依赖 + R8/D8 合并 dex + libxul.so 147MB + omni.ja），APK 从 68KB 变成 91MB。 修了 d8 内部错误（换 R8 9.5.29）、清单 90 个 Gecko 服务、zygotePreloadName、 主线程初始化等。目前仍在调 Gecko 初始化。

二、功能全貌（现在能干什么）

1. 桌面本身（HOME + LAUNCHER）

唯一 Activity ChatActivity，内部三页左右滑（横滑跟手 + 松手吸附，阈值 1/5 屏宽），底部三点可点循环：

页内容交互
Linux（最左）astrbot / napcat / dsh / voice_desk 端口探活 + ps 进程列表（5 秒刷新） 点一下 = 启动/重启；长按 = 停止（确认框）；$ run command… 执行任意命令
状态（默认）$ status --all：os/date/bat/mem/disk/uptime/net/svc/ports纯展示，5 秒刷新
消息终端日志风的人机对话（状态徽标、Markdown、失败重试、⚙ 应答设置、右上 [dsh] 打开 DSH 网页） 发消息、通知栏直接回复、点重试

2. 局域网 HTTP 控制端（192.168.0.103:8089，token dshdesk1）

接口作用
/ping探活，返回 desk-exec
/exec?cmd=以应用 UID（u0_a414）执行 shell，权限小
/termux?cmd=转交 Termux（u0_a199，完整工具链），依赖 allow-external-apps
/ui/on|shot|dump|tap|long|swipe|global|text|click无障碍：截图、读界面树、点击/长按/滑动、系统键、输入文字、按文字点击
/status电量/内存/存储/运行时长/IP/服务端口聚合
/logs?which=napcat|astrbot&lines=服务日志尾部
/svc?name=astrbot|napcat&action=start|stop|restart服务启停
/chat /chat/send?from=ai|user&text=&reply_to=读写消息；from=user 触发应答引擎，from=ai 通知手机
/chat/retry /chat/brain /chat/config重试 / 查看引擎 / 改应答配置（key 打码返回）
/token /webauthNapCat WebUI token（60 秒缓存）/ 网页口令读写
/dshurl存/读容器里 DSH Web 的带 token 地址

所有响应带 CORS（Access-Control-Allow-Origin: *），ESP32 托管的网页可直接跨端口取数。

3. 网页桌面（8090，公网/内网）

口令登录（HttpOnly Cookie，7 天，失败 5 次/分钟限速）。页面：状态卡片、服务日志、 消息收发、服务启停、NapCat token。安全边界：执行类接口在该端口一律 404。

4. 与电脑上 AI 助手的联动

中继模式（默认）：手机发消息 → 电脑上的 DSH 会话看到 → 助手把回复写回 /chat/send?from=ai&reply_to= → 手机通知 + 消息页 + 可朗读/上小屏。

直连模式：可切「OpenAI 兼容」或「本机 AstrBot」，手机自己问模型（已配置 api.deepseek.com + deepseek-chat，实测能回话）。

5. 语音 + 小屏（Termux 侧配套）

部件作用
~/voice_desk/screen_server.py :8091轮询 /chat，用 Pillow + 系统中文字体渲染成 80×160 RGB565 位图给 ESP32； 另有 /show?text= 可把任意文字直接上屏（DSH 回复就靠它）
~/voice_desk/voice_desk.py发现新的 AI 消息就 termux-tts-speak 用手机扬声器朗读
ESP32 reply_screen每 2 秒拉 /screen.bin（25600 字节）刷 ST7735
容器内 DSH 的 AGENTS.md要求它每次回答后 curl /show 推摘要上小屏

三、技术架构要点

进程与权限

  • App 本身 UID u0_a414，Termux u0_a199——通过 com.termux.RUN_COMMAND 桥接，结果经 /callback 回传
  • 没有 root：pm install 被 SELinux 拒；系统 shell 无 screencap/input，所以截图/点击全靠无障碍服务
  • Termux 被冻结会导致「端口通但握手卡住」，点亮屏幕即可恢复；termux-wake-lock 依赖常驻通知

构建

aapt2 compile/link → javac(JDK17) → jar → d8/R8 → 打成 classes.dex → 注入 base.apk
→ 打 lib/*.so + assets → zipalign -p 4 → apksigner（正式 keystore）→ dist/phone-desk.apk

本地 build.ps1；CI 用 build.sh + 一次性密钥。v0.18.x 起额外需要 tools/fetch-geckoview.ps1|sh 先拉 GeckoView（.geckoview/，不入库）。

数据流

手机消息页 ──/chat/send(from=user)──▶ ChatStore 状态机
                                      ├─ relay: 等电脑 DSH 写回
                                      ├─ openai: 直连 api.deepseek.com
                                      └─ astrbot: 本机 AstrBot
      ChatStore ──▶ screen_server(8091) ──▶ ESP32 小屏
                └─▶ voice_desk ──termux-tts-speak──▶ 扬声器

四、踩过的坑（都是真实遇到并解决的）

现象原因修法
ESP32 一直「离线」targetSdk 31 默认禁明文 HTTPusesCleartextTraffic="true"
并发请求输出串台Termux 桥接临时文件同名每次请求唯一文件名
小屏渲染服务「半死」：/health 正常但 /state.json 卡死持锁时又调 rebuild()（不可重入锁）→ 死锁锁内只置标记，锁外重建
手机 IP 变了连不上（.9 → .11 → .103）DHCP 漂移统一用 ssh phone 别名，IP 变更只改 SSH 配置；ESP32 固件自动扫网段
APK 装不上/不弹安装框MagicUI 限制 + 无法静默安装scp 到 /sdcard/Download 后 am start VIEW，用户手点安装
消息页内嵌 DSH 白屏系统 WebView 太旧：Promise.withResolvers 缺失 + JS 新语法解析失败polyfill 只能救前者，语法层救不了 → 改 GeckoView
GeckoView 构建失败build-tools 自带 d8 遇到 media3 类内部错误改用 R8 9.5.29 的 D8
GeckoView 初始化抛异常IllegalThreadStateException: Expected thread 1引擎初始化必须放主线程
清单合并后 aapt2 报 unbound prefixGeckoView 清单用了 tools: 前缀根节点补 xmlns:tools
公网域名打不开整个域名被网络层按 SNI 阻断（同 IP 其他域名正常）暂停；隧道与配置本身正常
